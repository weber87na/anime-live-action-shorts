# 已選圖後：動態生成

只有 `selection_gate.py check` 成功且對話已有真實使用者確認，才進入此階段。每次提交前重新檢查；核准表和生成 manifest 應一對一對應每個角色的所選候選與雜湊。多角色共用一鏡也要保存這個對應。

## 後端與提示詞

使用使用者指定或環境已可用的後端。H3 環境先發現 `minimax-h3-colab/SKILL.md`，讀取目前安裝版本，不硬寫 Windows 使用者、WSL distro、Linux home、GPU 型號或 Colab session。找不到時說明缺少什麼，先完成其他獨立準備工作；不要聲稱已生成影片，也不要悄悄換成靜態縮放。

在 H3 中保持參考圖次序與 `<Picture 1>` 對應穩定。依其技能撰寫 `subject_definitions`、`summary`、`retention_analysis`、含時間區間的 `detailed_description`、`overall_soundscape`、`non_diegetic_music`。提示詞內容取自本次專案，母圖鎖定已選人像，動作可按角色調整：自然呼吸、眨眼、微小轉頭、衣髮受風、穩定站姿等。使用者想要戰鬥動作時改成相符動作，不能讓模板限制創作方向。

鏡頭留足頭飾、髮頂、手及道具空間；緩慢拉遠常比推近更容易保留完整造型，但首幀本身也必須安全。生成時預留剪輯與轉場所需可用長度；模型原生輸出解析度與最終交付解析度分開記錄。

## H3 提交與續跑

1. 寫 UTF-8 manifest，從核准表取 `reference_images`。所有路徑在執行環境中須可讀；Windows／WSL 路徑轉換只改位置表示，轉換後重新核對檔案雜湊。
2. 使用安裝版本支援的 `batch --dry-run` 驗證設定，再以 `usage --json` 查看可用額度與狀態。品質遵從使用者偏好及安裝版本預設，額度足夠不代表一定能取得 GPU。
3. 一批循序產生，重用同一個執行階段，保留每個已完成 MP4 及模型設定側錄。只結束本次擁有的執行階段，依安裝技能處理其清理。
4. 斷線／逾時後先查遠端執行與佇列狀態；工作是否仍在進行不明時，不重送推論。確認失敗後才針對未完成項目續跑。

跨 Windows／WSL 且進度檔的原子替換被讀取鎖定時，將生成程式的進度檔留在 Linux 原生暫存目錄，另提供 Windows 可讀快照；讀取端容忍暫時未完成的 JSON。只有遇到此類實際錯誤才需此處理，不把單機 CLI 修補程式當成所有環境的依賴。

## 生成後檢查

以 probe 讀實際秒數、影格率及解析度；請求 5 秒不表示一定恰為 5 秒。檢查首、中、末影格與整段動作，尤其是母圖臉孔、年齡感、體格、服裝、手、冠飾、背景和鏡頭穩定度。做無時間碼的首末幀圖，避免檢查標籤遮住髮頂或頭飾。

可用區間不足時，依序評估重選原速區間、調整剪輯配置、或僅重製問題鏡頭。若重製仍使用同一已核准母圖及外貌，不必重問選圖；換臉、換候選或改外貌則回到選圖確認。

記錄每支影片：角色 ID、候選 ID、母圖 SHA-256、提示詞路徑、生成設定、影片路徑／雜湊、原生規格、可用入出點與 QA 結果。續跑時用這份明確對照，不掃描「最新檔案」作為來源。
